# 更新與效力管理政策

## 排程（臺灣時間）

| 工作流程 | 時間 | 內容 |
|---|---|---|
| update-laws（daily） | 每日 03:20 | 全國法規資料庫全部目標法規；RMIS 函釋列表前 3 頁＋異動明細；RMIS 法規現行內容；`auto_sync` 縣市之審核列入地方規定＋候選清單；林保署公文函釋前 3 頁、農業綠能函釋前 2 頁之新增明細（weekly 讀全部列表） |
| update-laws（weekly） | 每週日 02:40 | 上述＋RMIS 函釋全部 172 頁列表完整比對、歷史沿革、法規對應函釋 |
| update-technical | 每週四 03:50 | 農業資料開放平臺出版品目錄 |
| source-audit（monthly） | 每月 1 日 04:30 | 所有來源連線及 robots 重新檢查；重新搜尋開放資料目錄；全部函釋明細重新比對 |
| watchdog | 每日 12:10 | 檢查每日來源 50 小時內是否成功；逾時開 Issue；重新啟用被停用之排程 |

GitHub Actions 排程以 UTC 設定，已換算為臺灣時間。GitHub 不保證排程準時或永久執行，可能延遲數十分鐘。

## 同步安全規則

1. 來源連線失敗、被 robots 拒絕、回傳格式異常：該來源本次**不寫入任何資料**，紀錄為「檢查失敗」。
2. 完整列表筆數少於既有筆數 80%：整批**隔離**至 `data/quarantine/`，不套用。
3. 完整列表中消失的函釋：**不刪除**，標示 `source_missing_since`。
4. 每筆資料寫入前驗證（字號、日期、來源網址、不含 HTML 原始碼）；不合格者拒收並記錄。
5. 單一來源例外不影響其他來源。
6. 網站建置失敗時不部署，正式網站維持上一版。

「已成功檢查、無資料異動」與「檢查失敗」在紀錄與網站上分開顯示。

## 函釋效力狀態

| 狀態 | 條件 | 是否人工確認 |
|---|---|---|
| 已確認存在，尚無已查得之停止適用資訊 | 預設值 | 否（不代表有效） |
| 可能受法規修正影響 | 函釋引用之條文（系統比對）或整部法規（官方列示）在發文日後修正；修正範圍依沿革文字判斷，管轄變更公告不計 | 否 |
| 後續函釋有變更或補充 | 後續函釋文字以「前開／上開…函…補充／修正」提及本函字號 | 否 |
| 效力待人工查核 | 後續文件以「停止適用／不再適用／不再援用」等明文提及本函字號 | 否 |
| 官方明確停止適用／廢止或撤回 | 僅能由 `config/relations/manual.yaml` 人工登錄並附官方依據 | 是 |

系統不以 AI 判斷效力，也不會自動將任何函釋標為「現行有效」或「失效」。

## 修法影響追蹤

法規內容雜湊改變時：保留新舊版本快照 → 比對變動條號（`change_log`）→ 重新計算引用該條文之函釋 → 標示「可能受法規修正影響」並列出修正日期與沿革 → 不刪除任何歷史函釋。

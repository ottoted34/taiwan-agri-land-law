# 評估：以 Google 表單收集各縣市地方規定

結論：**可行，建議與 GitHub Issue 表單並行**。Google 表單做為「沒有 GitHub 帳號的同仁」的入口，收錄仍一律經管理者審核（`docs/maintenance.md` 第 5 節），不自動上線。

## 比較

| 項目 | GitHub Issue 表單（已建立） | Google 表單 |
|---|---|---|
| 填寫門檻 | 需 GitHub 帳號 | 不需帳號，手機好填，同仁較熟悉 |
| 內容公開性 | 公開（任何人可見） | 只有表單擁有者看得到回應試算表 |
| 審核紀錄 | Issue 留言即紀錄，可直接連到收錄設定 | 需在回應試算表自行加「審核狀態」欄 |
| 與網站資料串接 | 管理者依 Issue 修改 `config/local/counties.yaml` | 同左，需人工轉入（不建議自動串接，見下） |
| 個資風險 | 內容公開，誤填個資會被看見 | 不公開，但要注意是否收集 Email |
| 機關網路 | 一般可連 | 部分機關限制外部雲端服務，請先確認 |
| 濫用／垃圾填寫 | 需登入，較少 | 無門檻，靠「官方網址必填＋驗證」與人工審核把關 |

## 建議設定

建立者：Repository 擁有者以自己的 Google 帳號建立（本專案不保存任何 Google 帳密）。

**表單題目**（與 Issue 表單一致）：

1. 縣市（下拉選單，22 縣市）— 必填
2. 法規名稱（簡答，請照官方全銜）— 必填
3. 官方網址 — 必填；「回應驗證」選「規則運算式／符合模式」，填 `^https?://([A-Za-z0-9-]+\.)*gov\.tw/.*`，錯誤訊息「請填政府機關網域（gov.tw）之官方網址」
4. 發布或最新修正日期（簡答，例：民國113年2月21日，府授農地字第1130041756號令）— 必填
5. 施行日期（簡答；官方未載明者填「未載明」或「自發布日施行」）— 必填
6. 提供者單位（簡答，只填機關或單位名稱）— 選填
7. 補充說明（段落）— 選填
8. 確認事項（核取方塊，必填）：「我提供的是已公開之官方資料」、「本表單未包含個人資料或個案資料」

**表單說明欄**（建議文字）：

> 本表單供各縣市同仁提供農地相關地方規定（自治法規、審查要點等）。請只填已公開之官方資料並附官方網址，**勿填寫姓名、電話、身分證字號、地號或個案資料**。所填內容僅供「農地法規函釋知識庫」（非官方網站）管理者審核收錄使用，經核對官方網址後才會上線；收錄不代表機關認可。

**設定**：

- 設定 → 回覆 → 「收集電子郵件地址」選 **不收集**；不要開「限制只能回覆 1 次」（會強制登入 Google）。
- 「查看結果摘要」關閉；回應試算表**不要**設為「知道連結者可檢視」。
- 回應試算表加三欄：`審核狀態`（待審／收錄／不收錄）、`審核人`、`審核日期與理由`。

## 處理流程

1. 管理者每週查看回應試算表（可在表單設定「新回覆時以 Email 通知」）。
2. 依 `docs/maintenance.md` 5-1 核對官方網址、內容與相關性。
3. 收錄：修改 `config/local/counties.yaml`（`basis` 填核對之官方頁面，`issue` 可填「Google 表單第 N 筆回應」），並在試算表填審核結果。
4. 若內容誤含個資：刪除該筆回應（表單「回覆」頁與試算表都要刪）。

## 不建議的做法

- **以 Apps Script 自動把回應寫入 GitHub**：需要把 GitHub 權杖存在 Google 帳號中，外洩即可修改本專案；且自動化會跳過人工審核。量少時人工轉入即可。
- **把回應試算表公開或嵌入網站**：可能外洩誤填之個資。

## 網站連結

建立後把表單網址告訴維護者，或自行修改 `web/src/pages/Sources.tsx` 的 `GOOGLE_FORM_URL`（留空則不顯示），網站「資料來源 → 地方規定」會在「提供地方規定（GitHub）」旁多一個「以 Google 表單提供」按鈕。
